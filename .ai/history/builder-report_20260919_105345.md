## W1: Create src/missiles.js with ballistic missile and 30 m fireball system

W1 is implemented in src/missiles.js (the only file in scope) and the build passes.

What was done:
- createMissileSystem(scene, getGroundHeight) returns { fire(origin, forward, speed): boolean, update(dt): void }.
- fire() spawns a cone-mesh missile at origin with velocity forward*(speed+60); returns false without spawning if within the 1 s cooldown.
- update(dt) integrates gravity (-9.81 m/s² Y) per frame; when pos.y <= getGroundHeight(pos.x,pos.z) the missile mesh is removed from the scene and a fireball Group is added at the impact point.
- Fireball core: SphereGeometry scaled over 1.4 s, MeshBasicMaterial with AdditiveBlending, toneMapped:false, color lerping white→orange→red→transparent via COLOR_STOPS sampling.
- Fireball particles: THREE.Points with 60 vertices bursting radially over 2.2 s, PointsMaterial size 2.5 with AdditiveBlending.
- Fireball light: THREE.PointLight(0xff8822, 40, 80, 2) decaying to 0 intensity over 0.8 s.
- All fireball children are scene.remove()'d and geometry/material .dispose()'d once age exceeds 2.2 s (FIREBALL_LIFETIME).

Requester's "5x larger" improvement applied on top of spec:
- Core radius scales 10 m → 150 m (spec was 2 → 30 m, i.e. exactly 5x).
- Particle radial spread is 200 m (spec ~40 m, 5x).
- Durations unchanged (core 1.4 s, particles/lifetime 2.2 s, light fade 0.8 s), so it stays very easy to see.

Verification:
- Ran `npm run build` (vite production build): exit code 0, "✓ 1470 modules transformed", dist assets emitted successfully. No errors or warnings beyond the standard chunk-size note.

Caveats: none blocking. The missile meshes share one cached ConeGeometry/MeshStandardMaterial that is never disposed (intentional — reused across launches); individual missiles are removed from the scene on impact.
